## Finding: A11Y-004 — Semantische Struktur und Landmarks

| Feld | Wert |
|---|---|
| **Severity** | high *(eskaliert von medium — eCH-0059, WCAG 2.4.1 Level A)* |
| **Status** | open |
| **Lösung** | `future-skills-evidence-graph` |
| **Check-Reference** | `A11Y-004` |
| **WCAG/Heuristik-Ref** | WCAG 1.3.1, 2.4.1 (Bypass Blocks, Level A), 2.4.6 |
| **Audit-Datum** | 2026-07-18 |

| **Journey / Ort** | `einreichen.html`, `architektur.html` — alle Viewports |

### Observed Behavior

Überschriften-Hierarchie und Landmarks sind auf allen drei Seiten sauber
(genau ein `<h1>`, lückenlose h1→h2→h3, `<main>`/`<nav>`/`<header>` vorhanden,
Datentabelle mit `<caption>` + `<th scope>`). **Aber:**

- Der Skip-Link («Zum Inhalt springen») existiert nur auf `index.html`. Auf
  `einreichen.html` und `architektur.html` fehlt er komplett — Tastatur-/
  Screenreader-Nutzer haben keinen «Bypass Blocks»-Mechanismus, um die
  wiederholte Kopfnavigation zu überspringen.
- Keine Seite hat ein `<footer>`-Landmark. Fusszeilen-Inhalte
  (`.pipeline-foot`, `.arch-footnote`) liegen als `<p>` frei in `<main>`.

Messung (Browser-Begehung, `audit/evidence/2026-07-18-browser-walk.json`):

```
index.html       : hasSkipLink = true   landmarks {main:1, nav:1, footer:0}
einreichen.html  : hasSkipLink = false  landmarks {main:1, nav:1, footer:0}
architektur.html : hasSkipLink = false  landmarks {main:1, nav:1, footer:0}
```

### Expected Behavior

Skip-Link als erstes fokussierbares Element auf **jeder** Seite (2.4.1). Aller
Hauptinhalt in Landmark-Regionen; Fusszeilen-Inhalt in `<footer>`.

### Evidence

- File: `site/index.html:41` — `<a class="skip-link" href="#skillList">…</a>` (vorhanden)
- File: `site/einreichen.html` — kein `.skip-link` im `<body>` (fehlt)
- File: `site/architektur.html` — kein `.skip-link` im `<body>` (fehlt)
- Messung: `audit/evidence/2026-07-18-browser-walk.json` → `einreichen.structure.hasSkipLink = false`, `architektur.structure.hasSkipLink = false`
- CSS ist bereits da: `site/assets/styles.css:51` (`.skip-link`) — nur das Markup fehlt auf zwei Seiten.

### Risk Description

Screenreader- und Tastaturnutzer müssen sich auf `einreichen.html` und
`architektur.html` bei jeder Ankunft durch die komplette Topbar (Logo, 2–3
Nav-Links, Theme-Toggle) tabben, bevor sie den Inhalt erreichen. Für ein
Werkzeug mit eCH-0059-Anspruch ist der fehlende Bypass-Mechanismus ein
Konformitätsverstoss (WCAG 2.4.1, Level A).

### Remediation

Denselben Skip-Link wie auf `index.html` in beide Seiten einsetzen (CSS ist
bereits global vorhanden), Ziel-`id` auf das jeweilige `<main>`:

```diff
  <body>
+   <a class="skip-link" href="#hauptinhalt">Zum Inhalt springen</a>
    <header class="topbar">
    …
-   <main class="shell submit-shell">
+   <main class="shell submit-shell" id="hauptinhalt" tabindex="-1">
```

Optional (Feinschliff, medium): Fusszeilen-Inhalte in `<footer>` verschieben.
