## Finding: A11Y-002 — Sichtbarer Fokus-Indikator

| Feld | Wert |
|---|---|
| **Severity** | high *(Basis high; eCH-0059-Eskalation zu critical durch Teil-Ersatz zurückgestuft — siehe Anhang)* |
| **Status** | in-remediation |
| **Lösung** | `future-skills-evidence-graph` |
| **Check-Reference** | `A11Y-002` |
| **WCAG/Heuristik-Ref** | WCAG 2.4.7, 2.4.11 (Level AA) |
| **Audit-Datum** | 2026-07-18 |
| **Auditor** | Claude (ux-audit Skill) |
| **Journey / Ort** | `architektur.html` (Ansicht-Tabs), `einreichen.html` (Formularfelder) |

### Observed Behavior

Global ist der Fokus vorbildlich gelöst: `:focus-visible { outline: 2px solid
var(--focus); outline-offset: 2px }` greift auf Links, Buttons, Selects, Skill-
Cards und sogar den SVG-Architektur-Knoten (Begehung bestätigt überall ein
sattes 2px-Outline). **Zwei Komponenten setzen dieses Outline aber per
`outline: none` ausser Kraft und ersetzen es nur schwach:**

1. **Architektur-Ansicht-Tabs** (`Systemfluss` / `Datenmodell`): beim Tabben
   **kein Outline** (`outlineStyle: none, outlineWidth: 0px` gemessen). Der
   einzige Fokus-Hinweis ist ein Wechsel der 1px-Rahmenfarbe auf `--green` —
   **dieselbe grüne Rahmenfarbe, die auch der aktive Tab trägt.** Fokus auf dem
   inaktiven Tab ist damit visuell nicht von «aktiv» unterscheidbar.
2. **Formularfelder & Dropzone** (`einreichen.html`): Fokus-Outline ist
   `2px solid rgba(49,95,159,0.25)` — bei 25 % Deckkraft auf Weiss ≈ 1.3:1
   Kontrast, deutlich unter den geforderten 3:1. (Der gleichzeitige Wechsel der
   Rahmenfarbe auf `--blue` liefert einen schwachen, aber vorhandenen 1px-Ersatz —
   deshalb Teil-, nicht Totalausfall.)

Messung (`audit/evidence/2026-07-18-browser-walk.json`, Tastatur-Durchgang):

```
architektur.focus → .arch-tab is-active : outlineStyle "none", outlineWidth "0px"
architektur.focus → .arch-tab           : outlineStyle "none", outlineWidth "0px"
einreichen.focus  → INPUT / TEXTAREA / .dropzone : outlineColor "rgba(49,95,159,0.25)"
```

### Expected Behavior

Jedes interaktive Element zeigt einen **deutlich sichtbaren** Fokus-Zustand mit
≥ 3:1 Kontrast, der sich vom Ruhe- **und** vom Aktiv-Zustand unterscheidet;
`outline: none` nur mit gleichwertigem Ersatz (WCAG 2.4.7).

### Evidence

- File: `site/assets/architektur.css:56-60`
  ```css
  .arch-tab:hover,
  .arch-tab:focus-visible {
    border-color: var(--green);
    outline: none;           /* kein gleichwertiger Ersatz; kollidiert mit .is-active */
  }
  ```
- File: `site/assets/submit.css:65-70`
  ```css
  .submit-card input:focus,
  .submit-card textarea:focus,
  .dropzone:focus {
    border-color: var(--blue);
    outline: 2px solid rgba(49, 95, 159, 0.25);   /* ≈ 1.3:1, < 3:1 */
    outline-offset: 1px;
  }
  ```
- Screenshot: `audit/screenshots/einreichen-input-focus.png`
- Messung: `audit/evidence/2026-07-18-browser-walk.json` (`architektur.focus`, `einreichen.focus`)

### Risk Description

Tastaturnutzer, die zwischen «Systemfluss» und «Datenmodell» wechseln, sehen
nicht, welcher Tab gerade fokussiert ist — der Fokus verschmilzt mit dem
Aktiv-Zustand. Auf dem Einreichungsformular ist der Fokusring so blass, dass er
bei Sonnenlicht / günstigen Displays verschwindet. Beides trifft genau die
Nutzer, die auf klare Fokus-Führung angewiesen sind (motorische Einschränkung,
Screen-Vergrösserung).

### Remediation

Das globale `:focus-visible` einfach greifen lassen statt es zu überschreiben:

```diff
  .arch-tab:hover,
- .arch-tab:focus-visible {
+ .arch-tab:hover {
    border-color: var(--green);
-   outline: none;
  }
```

```diff
  .submit-card input:focus,
  .submit-card textarea:focus,
  .dropzone:focus {
    border-color: var(--blue);
-   outline: 2px solid rgba(49, 95, 159, 0.25);
-   outline-offset: 1px;
+   outline: 2px solid var(--focus);
+   outline-offset: 2px;
  }
```

## Anhang: Severity-Begründung

Basis-Severity `high` (2.4.7/2.4.11, Level AA). Unter eCH-0059 würde ein reiner
2.4.7-Ausfall zu `critical` eskalieren. Da beide Stellen einen — wenn auch
schwachen — Rahmenfarb-Ersatz besitzen (kein Totalausfall des Indikators),
wird um eine Stufe auf `high` zurückgestuft. Dokumentierte Down-Stufung gemäss
Finding-Template.
