### Observed Behavior

**Labels sind korrekt:** alle drei sichtbaren Felder (Quellen-URL, Herausgeber,
Erscheinungsjahr) und das Textfeld sind über umschliessende `<label>` benannt;
die versteckte Datei-Eingabe wird über eine `role="button"`-Dropzone mit
`aria-label` bedient. Der Fehlerhinweis `#submitHint` trägt `aria-live="polite"`
und beim Absenden ohne URL springt der Fokus korrekt auf `#urlInput`.

**Was fehlt** (Browser-Begehung + Code):

- Der Fehlertext wird **nicht programmatisch dem Feld zugeordnet**: kein
  `aria-invalid` auf `#urlInput`, kein `aria-describedby` auf den `#submitHint`.
  Screenreader hören zwar die Live-Region, das Feld selbst meldet aber weder
  «ungültig» noch verweist es auf die Fehlerursache (WCAG 3.3.1 / 4.1.2).
- Pflichtfelder tragen kein `aria-required`/`required`; die Pflicht ist nur
  visuell über ein rotes `*` markiert (`.req`).
- Kein `autocomplete` auf den Feldern (geringere Relevanz — keine Personendaten).
- Der Block ist kein `<form>`-Element (`isForm = false`), daher keine native
  Constraint-Validierung und kein Enter-zum-Absenden.

Messung (`audit/evidence/2026-07-18-browser-walk.json`):

```
formFields: url/publisher/year/textarea → labelled:true, autocomplete:null
submitValidation: hint "Bitte eine Quellen-URL angeben (Pflichtfeld)."
                  hintLive "polite", focused "urlInput"
                  → aber kein aria-invalid / aria-describedby auf #urlInput
```

### Expected Behavior

Validierungsfehler sind dem Feld zugeordnet (`aria-describedby` + `aria-invalid`)
und werden angekündigt; Pflichtfelder sind programmatisch als Pflicht erkennbar.

### Evidence

- File: `site/einreichen.html:74` — `<input id="urlInput" type="url" …>` ohne `aria-describedby`/`aria-required`
- File: `site/assets/submit.js:299-311` — `onSubmit()` setzt nur `setHint(...)` + `els.url.focus()`, setzt kein `aria-invalid`
- File: `site/einreichen.html:106` — `<p id="submitHint" … aria-live="polite">` (Live-Region vorhanden, aber nicht referenziert)
- Messung: `einreichen.submitValidation` (s.o.)

### Risk Description

Ein Screenreader-Nutzer, der das Formular ohne URL absendet, hört den Live-Hinweis,
aber beim Zurücknavigieren zum Feld gibt es keine programmatische Verbindung
«dieses Feld ist fehlerhaft, weil …». Bei kognitiver Einschränkung oder wenn die
Live-Ansage verpasst wurde, bleibt unklar, welches Feld das Problem ist. Für
eine öffentliche Hand (eCH-0059) ist die fehlende Fehler-Feld-Zuordnung ein
Verstoss gegen WCAG 3.3.1 (Level A).

### Remediation

```diff
- <input id="urlInput" type="url" inputmode="url" placeholder="https://…" />
+ <input id="urlInput" type="url" inputmode="url" required aria-required="true"
+        aria-describedby="urlHint" placeholder="https://…" />
```

In `submit.js` bei Fehler das Feld markieren und den Hinweis referenzieren:

```diff
  if (!url) {
+   els.url.setAttribute("aria-invalid", "true");
+   els.hint.id = "urlHint";
    setHint(text ? "…" : "Bitte eine Quellen-URL angeben (Pflichtfeld).", "error");
    els.url.focus();
    return;
  }
+ els.url.removeAttribute("aria-invalid"); // bei erfolgreicher Prüfung zurücksetzen
```
