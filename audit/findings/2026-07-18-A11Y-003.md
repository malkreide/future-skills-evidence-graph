## Finding: A11Y-003 — Textalternative für das Architektur-Diagramm

| Feld | Wert |
|---|---|
| **Severity** | medium *(Basis high; Textalternative existiert bereits über Detailpanel → nur Container-Name fehlt)* |
| **Status** | open |
| **Lösung** | `future-skills-evidence-graph` |
| **Check-Reference** | `A11Y-003` |
| **WCAG/Heuristik-Ref** | WCAG 1.1.1 (Level A) |
| **Audit-Datum** | 2026-07-18 |
| **Auditor** | Claude (ux-audit Skill) |
| **Journey / Ort** | `architektur.html` — SVG-Diagramm |

### Observed Behavior

Das Radar-Canvas auf `index.html` ist vorbildlich: `role="img"` + beschreibendes,
datengetriebenes `aria-label` («Netzdiagramm: Future Evidence gegen LP21-Abdeckung
für 14 Future Skills …») und die vollständigen Werte stehen zusätzlich in der
Tabelle. Keine `<img>` ohne `alt`, keine unbenannten Icon-Buttons.

Das **Architektur-SVG** dagegen (`#archSvg`) trägt `role="group"` **ohne
zugänglichen Namen** (`aria-label = null`, kein `<title>`). Die einzelnen Knoten
sind zwar je `role="button"` mit `aria-label` (Knotentitel), aber der Graph als
Ganzes — inklusive der Fluss-Beziehungen (Pfeile/Kanten) — hat keine
programmatische Zusammenfassung.

Messung (`audit/evidence/2026-07-18-browser-walk.json`):

```
architektur.hydration.svgHasName: { role:"group", ariaLabel:null, title:false }
architektur.svgNodeKeyboard: { tabindex:"0", role:"button", ariaLabel:"Externe Quellen-APIs" }
```

**Mitigierend:** Der Intro-Text (`.arch-intro` + Detailpanel `#archDetail`,
`aria-live="polite"`) beschreibt Zweck und Bausteine in Prosa; jeder Knoten
liefert bei Aktivierung seine Rolle/Dateien/Regeln als Text. Die inhaltliche
Alternative ist also vorhanden — nur der SVG-Container ist nicht benannt und die
gerichteten Kanten sind rein visuell.

### Expected Behavior

Das Diagramm hat einen zugänglichen Namen (`aria-labelledby` auf die Überschrift
oder ein `<title>`) und eine kurze Textzusammenfassung seiner Aussage.

### Evidence

- File: `site/architektur.html:78` — `<svg id="archSvg" role="group" preserveAspectRatio="…">` (kein `aria-label`/`<title>`)
- File: `site/assets/architektur.js:390-476` — `render()` erzeugt Knoten mit `aria-label`, aber keinen Namen/Titel für das Wurzel-`<svg>`
- Vergleich (positiv): `site/index.html:238-243` + `site/assets/app.js:680` — Radar-Canvas mit `role="img"` und dynamischem `aria-label`

### Risk Description

Screenreader-Nutzer bekommen beim Betreten des SVG «Gruppe» ohne Kontext
angesagt; die Richtung des Prozessflusses (was folgt worauf) ist nur visuell
codiert. Da Intro und Detailpanel den Inhalt aber in Textform tragen, ist der
Informationsverlust begrenzt.

### Remediation

```diff
- <svg id="archSvg" role="group" preserveAspectRatio="xMidYMin meet"></svg>
+ <svg id="archSvg" role="group" aria-labelledby="archSvgTitle archSvgDesc"
+      preserveAspectRatio="xMidYMin meet">
+   <title id="archSvgTitle">Systemfluss: von der Quelle zur Empfehlung</title>
+   <desc id="archSvgDesc">Interaktives Diagramm; die vollständige Beschreibung
+     steht im Textpanel rechts. Bausteine per Tab und Enter öffnen.</desc>
+ </svg>
```
Beim View-Wechsel `<title>`/`<desc>` in `setView()` mitschreiben (Fluss vs. Datenmodell).
